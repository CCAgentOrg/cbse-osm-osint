New OSINT Evidence: Coempt's Internal Code on GitHub, 30+ Board Subdomains Exposed, and CBSE OSM Architecture

Published: 29 May 2026  |  Author: Cashless Consumer  |  Cross-referencing: Nisarga Adhikary, Sarthak Sidhant

TL;DR

  • 3 internal Coempt EduTeck repositories found on GitHub by employees segrgokul (Gokul, QA engineer) and viswanthp (Viswanth, developer) — containing full Selenium automation suites, page object models with XPath locators, credentials, and hardcoded API endpoints.
  • 30+ board subdomains exposed via SSL certificate transparency logs on *.onmark.co.in — CBSE, BCU, KSWU, ANU, MSU, SBTET, JNTU, GITA, and at least 20 more state boards and universities using the same OSM platform.
  • 77 unique API endpoints extracted from an archived Angular production bundle — including auth bypass routes, re-evaluation submission, QR code login, webcam test, IP/MAC address tracking, and Razorpay payment integration.
  • CBSE Class 12 evaluation was running on this system from at least 26 February 2026, but the vendor's own QA test suite had to be rewritten twice in 3 days (21 Feb → 24 Feb) because the live OSM portal kept changing mid-evaluation — a major red flag on system readiness.
  • All evidence archived at zo.pub/cashlessconsumer/cbse-coempt-osint-archive. No API keys, passwords, or specific credentials are disclosed in this post.
Correction to timeline: CBSE Class 12 board exams ran 15 Feb – 4 Mar 2026. The "Mass Mock Evaluation" circular was issued on 25 February — just 7 days before exams ended and the same window when Coempt's own QA code was being rewritten to track a moving target. The vendor's test automation was still chasing the live portal as students were finishing their last papers.

Background

Following Nisarga Adhikary's disclosure of critical vulnerabilities in CBSE's On-Screen Marking (OSM) portal at cbse.onmark.co.in, and Sarthak Sidhant's investigation into CBSE's tender process favouring Coempt EduTeck, we conducted independent OSINT to map the full technical attack surface and supply-chain scope of this system.

This post covers findings not present in either previous disclosure: internal QA automation code, the complete board client list, full API endpoint inventory, and a forensic timeline showing the system was unstable during active evaluation.

OCR Integration Pipeline

The automation code reveals three distinct OCR methods used in the evaluation pipeline:

  1. Tesseract OCR (local) — for extracting text from scanned answer sheet images
  2. Google Gemini Vision API — AI-powered image analysis of handwritten responses, with evaluation prompt engineering
  3. Custom OCR extraction modules — structured data extraction from PDF answer sheets via dedicated Ocr_Text_Extract classes

The Gemini integration is notable: the automation code contains carefully crafted evaluation prompts that instruct the AI to assess handwritten answers against marking schemes. This is part of the automated quality assurance layer — not the primary marking system, but an AI review of evaluator consistency.

Finding 4: The Portal Was Changing Mid-Evaluation

Coempt employee segrgokul's GitHub commit history provides a forensic timeline of the OSM portal's instability during CBSE evaluation:

Date (IST)Event
15 Feb 2026CBSE Class 12 board exams begin
25 Feb 2026CBSE issues "Mass Mock Evaluation" circular for OSM training
21 Feb 2026First OSM automation code pushed — osm_Login_Page.java (170 lines)
21 Feb 2026Screenshots captured from live cbse.onmark.co.in during testing
24 Feb 2026Complete rewrite — OSM login page, assessment page, and runner deleted and rewritten. XPath selectors changed. Screenshot page layout completely different.
3 Mar 2026Wayback Machine archives the Angular production bundle from live portal
4 Mar 2026CBSE Class 12 exams end
14 Mar 2026Gemini AI OCR integration added to automation
18 Mar 2026Final automation commit — OSM changes updated

The 21 Feb → 24 Feb rewrite is the critical finding. The vendor's own QA team was testing against a live OSM portal that was being modified underneath them during the same period CBSE was running mock evaluations. The XPath selectors, page layout, and DOM structure all changed between commits — meaning the live evaluation interface was not frozen.

This directly contradicts any claim that the system was production-stable before evaluation began.
