CBSE OSM Vendor Leaked Its Own Attack Code to GitHub

Coempt EduTeck's internal automation — pushed to public GitHub by its own employees — contains everything needed to script the entire CBSE evaluation portal, including bypassing the so-called OTP login.

By Cashless Consumer  |  29 May 2026  |  Cross-referencing: Nisarga Adhikary, Sarthak Sidhant
TL;DR
  • Three internal repositories belonging to Coempt EduTeck employees were found on public GitHub — containing full Selenium automation suites that exercise the CBSE On-Screen Marking portal.
  • The OTP protecting evaluator login is fake. It is generated client-side and displayed on the page itself. Coempt's own automation code proves this: it never reads or enters the OTP — it simply waits for the field to appear, then clicks Login.
  • The entire marking workflow is scriptable. The automation code demonstrates automated canvas-based marking, mark submission, and evaluation finalisation — designed to run unattended via Jenkins CI with parameterised credentials.
  • 30+ educational boards and universities use the same Coempt OSM platform, as revealed by SSL certificate records — meaning any vulnerability is shared across CBSE, Andhra Pradesh SBTET, Odisha SCTEVT, JNTU, and at least 20 more institutions.
  • The portal was unstable during live evaluation. Coempt's QA team had to rewrite their automation twice in three days (21→24 February) because the live OSM portal kept changing underneath them — even as CBSE was running mock evaluations.

What is the CBSE OSM?

The Central Board of Secondary Education (CBSE) uses an On-Screen Marking (OSM) system to evaluate Class 10 and Class 12 board exam answer sheets. Instead of physical paper packets shuffled between evaluators, scanned answer sheet images are displayed on a web portal where evaluators view, mark, and submit scores digitally.

The OSM platform is operated by Coempt EduTeck Pvt. Ltd., a Hyderabad-based company that won the CBSE contract. Their portal runs at cbse.onmark.co.in. Evaluators log in with credentials provided by their schools, view scanned answer sheets on an HTML5 canvas, allocate marks using right-click menus, and submit scores through the browser.

What We Found

Following earlier disclosures by security researcher Nisarga Adhikary (who found authentication bypass and client-side OTP vulnerabilities in the portal) and Sarthak Sidhant (who investigated the CBSE tender process), we conducted independent open-source intelligence (OSINT) to map the full technical scope.

Using GitHub searches, SSL certificate transparency logs, and the Wayback Machine, we discovered:

  1. Internal QA automation code — three GitHub repositories by Coempt employees containing Selenium test suites that interact with the live OSM portal
  2. Full client list — 30+ subdomains on *.onmark.co.in revealing every board and university using the same platform
  3. Complete API surface — 77 unique API endpoints extracted from an archived Angular production bundle
  4. A forensic timeline — showing the portal was being rewritten mid-evaluation

Why the OTP Is a Disaster

When an evaluator logs into the CBSE OSM portal, they are asked for four things: their username, password, school code, and date of birth. Then the portal displays a "Send OTP" button.

You would expect this OTP to be sent to the evaluator's registered phone or email — a second factor that proves the person logging in actually possesses the evaluator's device. That is how every serious system works.

That is not how this system works.

The OTP is generated entirely within the browser and displayed on the page itself. It is never sent to any phone or email. It appears as a plain text input field with the class name otp-input. The server does not validate any out-of-band token.

How do we know this? Because Coempt's own automation code handles the login flow, and it never reads the OTP value. It simply waits for the OTP field to appear on screen, checks that it is visible, and clicks the Login button. No OTP value is ever entered, because the field pre-fills itself.

This is not a one-time password. It is a client-side animation that creates the illusion of two-factor authentication while providing zero additional security. Any script — including Coempt's own Selenium automation — can bypass it trivially.

Scriptable Marking at Machine Speed

Once past the pseudo-OTP, the automation code demonstrates the full marking workflow:

  1. Navigate answer sheets — The code iterates through every scanned page of an answer booklet, clicking each page thumbnail to load it on the marking canvas.
  2. Allocate marks via canvas interaction — The marking interface uses HTML5 <canvas> elements. The automation right-clicks the canvas, selects a mark value from a context menu, and double-clicks to confirm — simulating a human evaluator at machine speed.
  3. Submit marks — The code interacts with the submission endpoints to save and finalise marks.

And here is what makes this a systemic risk rather than a theoretical vulnerability: the entire flow is designed to run on Jenkins CI/CD — a continuous integration server used for automated testing. The code accepts credentials from environment variables or Excel spreadsheets. Feed it a list of evaluator accounts, and one CI job can sequentially log in as each evaluator, auto-mark their assigned answer sheets, and submit — all unattended.

The Attack Chain
Step 1Obtain evaluator credentials (leaked in the same repos' config files)
Step 2Target the correct board URL (switchable via a single config value)
Step 3Log in — OTP bypasses itself, the code just waits for it to appear
Step 4Auto-mark answer sheets via canvas interaction at machine speed
Step 5Submit marks and move to the next evaluator account

The vendor's own employees wrote the proof-of-concept attack code and published it to a public repository.

The Portal Was Changing Under Evaluators' Feet

The automation code's commit history provides a rare forensic window into the system's stability during live evaluation:

15 FebCBSE Class 12 exams begin
21 FebCoempt QA pushes first OSM automation code — captures screenshots from the live portal
24 FebComplete rewrite — login page, assessment page, all XPath selectors deleted and rewritten. The live portal's layout and DOM structure had changed.
25 FebCBSE issues "Mass Mock Evaluation" circular for OSM training
3 MarWayback Machine archives the live Angular production bundle
4 MarCBSE Class 12 exams end
14 MarGemini Vision schema extraction for marksheet processing added to automation

The 21→24 February rewrite is the critical signal. CBSE's own mock evaluation circular went out on 25 February — but Coempt's QA team had already been forced to rewrite their automation because the live portal was changing underneath them before the mock even started.

The page layouts visible in the automation screenshots changed completely between commits. XPath selectors — the precise addresses of buttons and input fields on the page — were all different. This means the user interface that evaluators saw was not frozen. It was being modified in production during the evaluation window.
